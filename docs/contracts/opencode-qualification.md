## OCQ-01 — Exact real host and candidate

Use actual OpenCode Desktop 2.2.5 and the exact built plugin candidate. Exercise the real native
panel and main/window IPC, not substituted host mocks. Record actual runtime/SDK and input identities.

## OCQ-02 — Isolated execution

Use separate test configuration, sessions, protected secrets and store plus an isolated screen.
Do not change the owner's live installation or working sessions. Synthetic data only; no model calls
or external network during the test. Establish isolation before launch; failure is an explicit block,
not permission to reuse the live display/config. Preparation and execution are separate evidence.

## OCQ-03 — Complete in-harness decision journey

Open an exact request from the conversation, view the full canonical packet, choose approve/reject/
changes-required and observe the canonical outcome. Closing the panel leaves the request pending.
No external application/window or browser fallback substitutes for the native view.

## OCQ-04 — Binding, interruption and retries

Switching sessions/windows must not submit an answer for another request. Lost responses and plugin
reload retain the original exact command; retries do not duplicate resolution or rotation. Qualify
actual native lifecycle behavior, not a changed test assumption or a newly generated command key.

## OCQ-05 — Credential boundary

The owner credential must not enter conversation text, tool/RPC results exposed as model data,
the renderer, links or ordinary logs. The agent uses a separate key. T1 remains cooperative; no
new enterprise physical-human proof/hostile-same-user assurance is implied by this checkpoint.

## OCQ-06 — Visible failures and L-001

does not explain its earlier timeout. No increased timeouts or repeat-until-green execution without

## OCQ-07 — Bounded acceptance

The checkpoint qualifies only the actual assessed OpenCode/OS profile. Windows/macOS, abnormal
recovery and complete M1 remain separate gates. Installing into the owner's working profile requires
separate explicit permission. No such installation, public push or live keys follow from approval.
